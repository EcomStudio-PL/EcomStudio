## 5. Gotowe vs. wymaga decyzji

Gotowe w kodzie (testy zielone): parser bloków, polityka reguł obrazu, Prompt B b2, bramka planu, skala detalu, otoczenie, liczba sztuk, szkielet QC, logi admina.

Wymaga akceptacji / płatnego A/B:
1. Merge + deploy (bramka działa od razu dla wariantów **A i B** — klienci na wariancie A też dostaną blokadę twardych naruszeń).
2. Import kandydata v4.3 jako nowej wersji i aktywacja — dopiero wtedy reguły obrazu trafiają do NBP. **Przed aktywacją** poprawić w bloku `drabinka` zdanie „a osoba korzysta z właściwych stopni” na warunkowe („jeśli w scenie jest osoba…”), bo w hero bez ludzi może dorysować osobę.
3. A/B prompts-only (4 warianty: obecny / obecny + reguły / alternatywny model / alternatywny model + reguły) na oryginalnych zdjęciach HTC-2, potem A/B obrazów — budżet do zatwierdzenia.
4. Ręczna recenzja jakości: `applyReview()` gotowe, bez UI (zmiana UI poza zakresem).
